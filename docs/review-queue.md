- 2026-10-06 (step 9c): A rule of the format changed. The conversion to tbl now drops an excess GFM cell with no text, that is, a cell after the last column of the header with an empty text or only spaces and tabs between its pipes. Before, each excess cell failed the conversion. An excess cell with text stays an error at its line and column. If a row has several excess cells, the error names the first one with text. `docs/format.md` has the new rule. The reasons, values, and condition are in the entry 2026-10-06 (step 9) below. The change makes no valid block invalid and changes no content, so it is a fix (0.1.1), not a new minor version.
- 2026-10-06 (step 9): The corpus test compares what GFM shows. Before the comparison of the mdast, it removes the positions, pads short rows with empty cells, and removes excess cells, because GFM shows a short row padded and hides an excess cell. This is the meaning of "the file then renders the same" that the user agreed to for principle 1. The conversion to tbl will accept an excess cell with no text and drop it, because it holds no content and GFM hides it. An excess cell with text stays an error, because GFM hides content there and the writer must decide. The measurement of `docs/research/table-corpus.md` found 103 rows with excess cells in 6 of the 53 tables of public-apis, mostly an empty `| |`, and one with text. Values: reversibility (principle 1), no silent loss of content, human editing first (a whole file must not fail for an empty cell). Condition: GFM keeps hiding excess cells. If a renderer that we target shows them, the decision is open again.

- 2026-10-05 (step 4): A pipe after an even number of backslashes gets one backslash more in GFM, and the conversion to GFM fails for a pipe after an odd number. The measurement of micromark shows that GFM splits a cell at a pipe after an even number of backslashes, and that a code span gives no protection. The alternative was a run of k backslashes to 2k+1. It always converts, but it changes the meaning of each pipe after a backslash, in text and in a code span. One backslash more keeps the meaning, and a conversion from GFM never gives an odd number, so both round trips hold. The main thread decided this. Values: lossless round trip, one rule (one backslash more), no silent change. Condition: tbl cells with `\|` stay rare. If they are common, for example because writers escape pipes out of habit, the 2k+1 rule is the fallback.

Condition: such lines stay rare.

- 2026-10-05 (step 3): Rule 1 now says that the spaces around the info string do not count, that the language `tbl` is case-sensitive, and that an indented code block is no `tbl` block. This is how CommonMark and mdast read a fence, so the lint follows the platform. An error of a `tbl` block in the lint gets the column of the fence plus the column of the parse error minus one. All parse errors have column 1 now, so this is the column of the fence. An unclosed fence runs to the end of its container, as in CommonMark, so the lint reads it as a block. The problem codes `gfm-table` and `info-text` join the parse error codes in the type `ProblemCode`. Values: use the platform, precise errors. Condition: none.
- 2026-10-05 (step 2): The fence of the renderer counts each line that CommonMark reads as a closing fence: up to three spaces, three or more backticks, and then only spaces and tabs.
