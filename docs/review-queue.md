# Review queue

Decisions that this project made by the canon of values, newest first. Each entry has the date, the decision, the values it rests on, and its conditions. The user reads this file when they want to.

- 2026-10-05 (step 5): Details of the file conversion that the plan did not fix. The new section "Conversion of a file" of `docs/format.md` has them. `locate` gives `null` for a block with parse errors, because the lines of an invalid block have no clear meaning. An error of `toGfm` with no line (a problem of `validate`) is at the fence line. The column of each error of a `tbl` block is the column of the fence. A file with no line end gets LF. The self-check also checks that each table that stays keeps its kind and its text. If a new GFM table takes the next table as rows, only the first table gets an error, because one empty line fixes both. The measurement of micromark showed that a `tbl` block directly after a paragraph line converts (a GFM table can interrupt a paragraph), and that a lazy line after a list item or a block quote stays outside the table. Only a text line directly after the block, inside the same container, fails. Values: precise errors, no silent change, use the platform (the self-check reads the output with the same parser). Condition: micromark 2.1 reads tables this way. A newer version can change the cases, and the self-check catches each change.
- 2026-10-05 (step 4): A pipe after an even number of backslashes gets one backslash more in GFM, and the conversion to GFM fails for a pipe after an odd number. The measurement of micromark shows that GFM splits a cell at a pipe after an even number of backslashes, and that a code span gives no protection. The alternative was a run of k backslashes to 2k+1. It always converts, but it changes the meaning of each pipe after a backslash, in text and in a code span. One backslash more keeps the meaning, and a conversion from GFM never gives an odd number, so both round trips hold. The main thread decided this. Values: lossless round trip, one rule (one backslash more), no silent change. Condition: tbl cells with `\|` stay rare. If they are common, for example because writers escape pipes out of habit, the 2k+1 rule is the fallback.
- 2026-10-05 (step 4): The conversion to GFM fails for a cell line that ends with a backslash and has a next line, because the backslash would escape the `<br>` of the line break. A parity rule for `<br>` was the alternative, but it changes the rule `\<br>` to `\\<br>`. The main thread decided this. Values: lossless round trip, one rule, no silent change. Condition: such lines stay rare.
- 2026-10-05 (step 4): Details that `docs/format.md` did not fix. The first column with a key keeps it, and a later duplicate gets the smallest suffix that no other column has, so the titles `a`, `a`, `a-2` give `a`, `a-3`, `a-2`. An empty title gives `c` and the column number before the duplicate check. The conversion to tbl fails if the text before an ID marker ends with a space or a tab, because the cell could not convert back to GFM. A GFM row with fewer cells than the header has empty cells. An error of `toGfm` has the row (from 1) and the key, and an error of a title has no row. An error of `fromGfm` has the file line and the column of the cell. Values: lossless round trip, precise errors, readable keys. Condition: none.
- 2026-10-05 (step 4 plan): Spec principle 1 said that a round trip from `tbl` to GFM and back gives the same text. That cannot hold for the keys, because a GFM table has no keys, and the conversion to `tbl` makes them from the titles. The principle now names the content that survives (titles, cells, row IDs) and the canonical GFM text for the other direction. The alternative was to store the keys in GFM, for example in an HTML comment, but that adds noise to each GFM table for a rare round trip. Values: precise rules, readable output. Condition: if a user needs the keys back after a round trip, an HTML comment is cheap. This is a correction of `docs/spec.md` by the session, and the user can reverse it.
- 2026-10-05 (step 3): Rule 1 now says that the spaces around the info string do not count, that the language `tbl` is case-sensitive, and that an indented code block is no `tbl` block. This is how CommonMark and mdast read a fence, so the lint follows the platform. An error of a `tbl` block in the lint gets the column of the fence plus the column of the parse error minus one. All parse errors have column 1 now, so this is the column of the fence. An unclosed fence runs to the end of its container, as in CommonMark, so the lint reads it as a block. The problem codes `gfm-table` and `info-text` join the parse error codes in the type `ProblemCode`. Values: use the platform, precise errors. Condition: none.
- 2026-10-05 (step 2): The fence of the renderer counts each line that CommonMark reads as a closing fence: up to three spaces, three or more backticks, and then only spaces and tabs. Before, the rule named only a line of only backticks, so a line such as `   ```  ` could close the fence early. `validate` and the errors of `render` count columns and rows from 1, and an empty cell text gives no line, as a missing cell does. Values: lossless round trip, use the platform (the closing fence rule of CommonMark). Condition: none.
- 2026-10-05 (step 2): A line ends with LF, CRLF, or CR, as in CommonMark, and a title or a cell holds no CR. Before, the parser read only LF and CRLF, so a CR inside a line was content. Then a CR at the end of a cell line did not survive a render and a parse, and a lone CR in a Markdown file was a line end for CommonMark but not for the parser. The main thread decided this rule. `validate` reports each CR in a title or a cell. Values: lossless round trip, use the platform (the line ends of CommonMark), one rule. Condition: none.
- 2026-10-05 (step 1): Empty lines directly before a key line are not content either, so each cell drops its trailing empty lines. Before, rule 7 said that a cell never ends with an empty line, but its list missed this case. An empty line has no characters, and a line of only spaces is content. A block with no header record gives `no-header`, and a header of only text lines gives `header-not-key` for each line. With no header key, the parser does not read the data records, because each of their keys would be an error too. Each error has column 1, because each error is about the whole line. Values: precise rules for the parser and its tests, precise errors, canonical form. Condition: none.

- 2026-10-05 (format review): A conversion that would lose content fails with an error at the line and changes nothing. This covers a tbl cell that starts or ends with a space (GFM trims it) and a GFM cell that ends with `<br>` (a tbl cell cannot end with a line break). The alternative was a silent loss or a new escape. Values: lossless round trip (Q4 of the user), precise errors, no silent failure. Condition: the cases stay rare. If a measurement on real files shows them often, an escape is cheap.
- 2026-10-05 (format review): One escape rule for all marker forms: the text gets one backslash more than it has. The rule covers the key form, the separator form, a literal `<br>` in GFM, and a first GFM cell that ends with the form of an ID marker. Before, only the key form and the separator form had a precise rule, so `\<br>` in a tbl cell and a text `{#x}` at the end of the first cell did not survive the round trip. Cost: a tbl cell `\<br>` shows as `\<br>` after the conversion to GFM, not as `<br>`. Values: lossless round trip, one word one meaning (one rule). Condition: none.
- 2026-10-05 (format review): Only the exact text `<br>` becomes a line break in the conversion to tbl. `<br/>`, `<br />`, and `<BR>` stay text, so they survive the round trip with no escape. A `<br>` in a header title stays as it is in both directions, because a title has no line break. Values: lossless round trip, small rules. Condition: if real GFM files use `<br/>` for line breaks often, the converter can map it with a note.
- 2026-10-05 (format review): The info string is exactly `tbl`. Text after `tbl` is an error in version 0.x, so that a later version can give it a meaning, for example a table ID, with no breaking change. A tilde fence is also valid, but the renderer writes backticks. Values: deliver first, room for a later need without a major version. Condition: none.
- 2026-10-05 (format review): The header needs one key at least, a title can be empty (an empty GFM header cell gives `c1:`), and a line in the header that is no key line is an error. Values: precise errors, lossless round trip. Condition: none.
- 2026-10-05 (format review): The text of a key line starts after the colon and one space, and more spaces are content. A cell whose first line is empty renders as `key:` with no space. Empty lines at the start of the block and directly after `--` are not content, as the empty lines before `--` already were. A line that starts with `--` and is no separator is text. An ID has the form `[A-Za-z0-9_-]+`. Values: precise rules for the parser and its tests, canonical form. Condition: none.

The rule of the first copy ("a cell with three backticks") gave a longer fence also where CommonMark does not need it, for example for a code span in a cell. Values: canonical form, use the platform (the closing fence rule of CommonMark). Condition: none.
